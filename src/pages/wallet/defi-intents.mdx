# DeFi intents :badge[Partial]{warning}

DeFi integrations are installed Petals rather than native top-level Machine routes. The default Enso package owns its mounted interface under `/bloom/petals/enso/` and declares its exact route contract inside the installed package.

## Discover the installed contract

```sh
cat /bloom/docs/petals.md
cat /bloom/petals/enso/meta/route-contract.json
cat /bloom/petals/enso/README.md
```

Do not assume an old `/bloom/defi/intents/` route or a native `bloom-defi` authority path. Installed package documentation is authoritative for its version.

## Enso intent flow

The current Enso Petal accepts natural-language or JSON intents at its application mount:

```sh
echo 'swap 100 usdc to eth on base' \
  > /bloom/petals/enso/intents/alice/new
ls /bloom/petals/enso/intents/alice
cat /bloom/petals/enso/intents/alice/<session>/plan.md
cat /bloom/petals/enso/intents/alice/<session>/simulation.json
printf 'confirm\n' > /bloom/petals/enso/intents/alice/<session>/confirm
```

If an ERC-20 approval is required, the first Petal confirmation stages only the exact-amount approval in the standard wallet outbox. Review and confirm it, wait for a successful receipt, then confirm the Petal session again to simulate and stage the swap.

## Authority boundary

The Petal never receives a wallet private key and cannot contact Broker or Signer directly. It submits complete payload bytes through Machine. Broker checks installed-package provenance, route and operation scope, policy, and Sealed Approval limits; Signer owns any wallet or Petal-scoped delegated key and produces the signature.

Configuration, route names, slippage behavior, and provider requirements belong to the installed Enso package. Read its mounted `README.md` rather than relying on a floating package version.
