# What is Bloom? :badge[Partial]{warning}

Bloom is an agentic multi-chain wallet exposed as a virtual filesystem.

Instead of handing an agent RPC credentials, signing code, and a Web3 SDK, Bloom exposes wallet and chain operations as a filesystem. Agents already know how to navigate files. Bloom makes onchain work discoverable, auditable, and policy-gated through that interface.

```txt
/bloom/
  chains/<chain>/...      # live EVM chain state
  wallets/<name>/...      # public wallet state and staged account actions
  petals/<name>/...       # installed capability extensions
  watch/<id>/...          # live subscriptions
  simulate/<session>/...  # dry-run calls
  tools/...               # ABI, hashes, units, EIP-712 helpers
```

## Current product state

- read live EVM state and native Solana account state as files;
- register or import wallets through Broker-hosted custody ceremonies while Signer retains private keys;
- stage EVM intents and native SOL transfers through explicit numbered HD accounts;
- inspect a generated `plan.md` before signing;
- confirm a staged transaction only after user approval;
- enforce policy through spend caps, allow/deny lists, contract-call gates, private orderflow settings, and hash-chained audit logging;
- extend capabilities through Petals.

Bloom is an agentic wallet mounted as a virtual filesystem. Reads are blockchain queries. Writes stage transaction intents. Machine presents and executes the work, Broker enforces policy and approval, and Signer alone holds wallet keys and produces signatures.

## Petals

[Petals](/petals/overview) are small, composable, verifiable programs that extend Bloom with agent-safe capabilities such as a Polymarket trading workflow or a Hyperliquid strategy.

## Status

Bloom uses the separate-process [Triad Architecture](/reference/triad-architecture): a key-free Machine runtime, a Broker authorization service, and a Signer custody service. The Machine workspace contains the CLI, VFS, transaction staging, chain readers, Petal host, and optional NFSv4 mount adapter. EVM broadcast routing is enabled by default on configured chains; Solana mainnet broadcasting is disabled by default. Policy, approval, and signing remain mandatory safety boundaries.
